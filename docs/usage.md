# Использование и ограничения

## Работа с комнатой

1. Откройте главную страницу. Сервер создаёт комнату с шестисимвольным кодом, например `Q1W2E3`; адрес страницы становится `http://my-server:8080/Q1W2E3` (или HTTPS на вашем домене).
2. Введите имя: оно показывается рядом с курсором другим участникам. Имя не является аккаунтом и не сохраняется после перезагрузки страницы.
3. Выберите Python, SQL или Text. В Text обычный текст без подсветки синтаксиса. Тип общий для комнаты и сохраняется вместе с документом.
4. Нажмите «Копировать ссылку» и передайте её участникам. Они получают право редактировать. При размещении за общим паролем им также нужен пароль.
5. Редактируйте одновременно. Есть подсветка, номера строк, поиск, undo/redo и курсоры участников. Undo отменяет только ваши правки, сохраняя чужие изменения. Python и SQL не выполняются.
6. «Скачать» сохраняет текущий текст в `.py`, `.sql` или `.txt` соответственно. «Новая комната» создаёт отдельный документ и новый короткий адрес; прежняя остаётся в базе.

Новые коды состоят из A–Z и 0–9. Их можно продиктовать или ввести в адресе маленькими буквами: сервер перенаправит на канонический адрес с большими буквами. Копирование ссылки и обновление страницы сохраняют ту же комнату. Неизвестный адрес возвращает 404; новая комната создаётся через главную страницу или кнопку.

Сервер проверяет совпадения кодов, включая сохранённые документы, и повторяет генерацию при коллизии. Прежние ссылки вида `/#длинный-идентификатор` продолжают открывать тот же документ. Короткий код удобен для передачи, но не является паролем: для закрытого размещения используйте контроль доступа прокси из инструкции установки.

При локальном запуске ссылка `127.0.0.1` работает только на той же машине. Для других людей используйте домен развёрнутого сервера. Не размещайте секреты в общем документе: обладатель ссылки может прочитать и изменить его.

## Соединение и сохранение

«Подключено» означает, что клиент установил соединение и завершил синхронизацию. Это не подтверждение записи всех изменений на диск.

При потере связи редактор продолжает принимать правки в памяти вкладки и автоматически пытается переподключиться. После подключения правки объединяются с изменениями других участников. Пока соединения нет, не закрывайте и не перезагружайте вкладку; при необходимости скачайте текст. Постоянного локального хранилища несинхронизированных правок пока нет.

Сервер объединяет частые изменения в пачки: задержка 250 мс, максимальное окно 1 с, затем запись в SQLite. Последний участник может выйти — документ будет записан и выгружен из памяти. Ctrl+C/SIGTERM запускает корректное завершение с дренированием записей.

При SIGKILL или OOM могут потеряться правки, ещё не записанные сервером. SQLite использует WAL и `synchronous=NORMAL`; гарантия сохранения последних транзакций при аварии питания/ОС отличается от обычного перезапуска процесса.

## Текущие пределы

| Параметр | По умолчанию | Примечание |
| --- | --- | --- |
| Одновременно загруженные комнаты | 5 | Освобождаются после выхода последнего участника |
| Участники в комнате | 5 | Лишнее подключение получает HTTP 503 |
| Всего соединений | 25 | Произведение двух предыдущих настроек |
| Длина нового кода комнаты | 6 символов | Выдаётся сервером и сохраняется в SQLite |
| Входящее WebSocket-сообщение | 1 МиБ | Это размер сообщения протокола, а не итогового текста |
| Срок хранения документов | Без автоматического удаления | База остаётся на диске после выгрузки комнаты |

Ориентир для прототипа — документы около 100 КБ и не более 200 КБ. Жёсткий лимит итогового текста 200 КБ ещё не реализован. Длительная история правок может увеличивать память и объём синхронизации даже при коротком тексте. Лимит сообщения 1 МиБ может препятствовать повторному подключению к документу с большим CRDT-состоянием.

Для постоянной первой версии ещё нужны: создание комнат только владельцем, серверный предел итогового текста, автоматическое удаление старых комнат, проверка долгой работы и реального VPS с VPN. Сейчас прототип предназначен для доверенных участников с ограниченным доступом.

## Параметры запуска

Скопируйте `.env.example` в `.env` в корне проекта и измените нужные значения. Не перезаписывайте уже настроенный файл. При запуске из этого каталога сервер читает его автоматически:

```dotenv
KOSHA_HOST=127.0.0.1
KOSHA_PORT=8090
KOSHA_DATABASE=data/kosha.db
KOSHA_MAX_ROOMS=5
KOSHA_MAX_PEERS=5
KOSHA_MAX_MESSAGE_BYTES=1048576
KOSHA_METRICS=false
```

| Переменная | Встроенное значение | Назначение |
| --- | --- | --- |
| `KOSHA_HOST` | `127.0.0.1` | Интерфейс HTTP; для IPv6 указывайте `::1` без скобок |
| `KOSHA_PORT` | `8080` | Порт 1–65535; 0 выбирает свободный порт автоматически для тестов |
| `KOSHA_DATABASE` | `data/kosha.db` | Путь к постоянной SQLite-базе |
| `KOSHA_MAX_ROOMS` | `5` | Максимум одновременно загруженных комнат, 1–100 |
| `KOSHA_MAX_PEERS` | `5` | Максимум участников в одной комнате, 1–100 |
| `KOSHA_MAX_MESSAGE_BYTES` | `1048576` | Максимальный размер входящего WS-сообщения в байтах |
| `KOSHA_METRICS` | `false` | Включить приватную диагностику `/debug/metrics` |

Приоритет: явно переданные флаги → окружение процесса → `.env` → встроенные значения. Настройку можно разово переопределить без редактирования файла:

```sh
./bin/kosha -help
KOSHA_PORT=9000 ./bin/kosha
./bin/kosha -addr 127.0.0.1:9001 -db data/kosha.db -max-rooms 5 -max-peers 5
./bin/kosha -env-file /etc/kosha/.env
./bin/kosha -env-file ''
```

`-addr` переопределяет сразу host и port. Пустой `-env-file ''` отключает чтение файла, сохраняя переменные окружения. Отсутствие стандартного `.env` допустимо; явно указанный файл должен существовать. Неизвестные переменные не используются, неверные значения известных параметров останавливают запуск с ошибкой. Изменения применяются после перезапуска; пересборка не нужна.

В `.env` поддерживаются строки `KEY=value`, комментарии и кавычки. Относительный путь к базе считается от рабочего каталога процесса, а не от местоположения файла настроек. Локальный `.env` исключён из Git; в репозиторий входит только пример.

`-max-message-bytes` задаёт предел одного входящего сообщения. `-metrics` (или `KOSHA_METRICS=true`) включает `/debug/metrics` с диагностикой Go-памяти и количества комнат/обработчиков WebSocket. По умолчанию диагностики нет; она не должна быть доступна извне. Ограничения памяти systemd и параметры Go runtime настраиваются отдельно от этих параметров приложения.

Если отображается «Нет связи», проверьте доступность сервера, пароль прокси, лимиты комнат и участников, передачу WebSocket через прокси. При превышении лимита клиент будет пытаться подключаться снова; скачайте локальные правки и освободите комнату или подключение.
